# Interface translations

The UI text lives in message catalogs under `src/lib/i18n/messages`. Each
language is a single file mapping message keys to strings. `nl.ts` holds the
original Dutch text and defines the full set of keys. Every other catalog
(currently `en.ts`) has to provide exactly those keys, and the build fails if a
key is missing or extra, since `en` is typed as `Record<MessageKey, string>`.

`locales.ts` is the registry. It maps a language code to its display name and
its catalog. The `UiLanguage` type is derived from the registry keys, so the
rest of the app and the language picker pick up a new language on their own.

Components read text through the `useT()` hook in `provider.tsx`:

```ts
const t = useT()
t("rail.settings")                            // "Settings"
t("rail.progress.eyebrow", { level: "A2" })   // "Progress A2"
```

`{token}` placeholders are filled from the second argument. If a key is missing
from the active language it falls back to the Dutch text.

## Adding a language

1. Copy `messages/nl.ts` to `messages/<code>.ts` and translate the values.
2. Add one entry to `locales.ts`.

That is all. The check in `locales.test.ts` iterates over every registered
language and compares its keys against the base set, so a new catalog is
covered without editing the test.

`languages.ts` is a separate, longer list of codes used as targets when
translating lesson content, not for the interface itself.
